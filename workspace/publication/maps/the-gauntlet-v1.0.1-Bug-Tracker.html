01MAJORVERIFIED

Ordinary players can craft the developer level-skip item

BUG-GNT-DEV-SKIP
View Details ↓Collapse Details ↑
Issue
A normal player can craft a stick from authored level resources and use the release-enabled developer control to skip the current level for the arena.
How to Reproduce
  1. Reach Gauntlet Level 13 as a normal non-developer player.
  2. Take oak or dark-oak planks from the authored resource barrels.
  3. Craft a normal Minecraft stick.
  4. Use the stick and confirm the current level is skipped for the arena.
Observed
The stick-triggered skip is enabled without a permission check, and authored Survival resources provide planks that can be crafted into sticks.
Expected
Level-skip controls are disabled in release or require the existing developer permission before changing progression.
Resolution
Disable item-triggered developer skip/retry controls in release or gate them through the existing developer-permission owner.
Technical Analysis
The release enables devSkipLevel on minecraft:stick and the itemUse path executes the skip without developer authorization. The selected structure/resource flow provides planks to Survival players, closing the ordinary-player acquisition path.
Source Context
selected Gauntlet behavior-pack gameplay bundle — Defines enabled stick-based level skip and the unguarded itemUse progression mutation.
selected Gauntlet chest_build.mcstructure — Provides authored plank resources that ordinary Survival players can craft into the trigger stick.
Must Preserve
  • Authorized developer skip/retry workflows may remain available through the existing permission owner.

02MAJORVERIFIED

Co-op progression can ignore a disconnected required party member

BUG-GNT-DISCONNECT-GATE
View Details ↓Collapse Details ↑
Issue
All-player progression checks can drop an offline locked member, allowing the remaining player to advance cooperative gates without the full party.
How to Reproduce
  1. Start The Gauntlet with at least 2 players and reach an all-player progression gate such as Level 9.
  2. Disconnect one required party member before the group completes the gate.
  3. Move the remaining online player into the required completion area within the disconnect recovery window.
  4. Confirm the level advances even though the disconnected required member never completed the gate.
Observed
The shared all-player predicate filters the locked roster to currently present players before evaluating completion.
Expected
Progression gates requiring the locked party wait for every required member, or pause while one is disconnected.
Resolution
Evaluate required cooperative gates against the locked run roster, or pause those gates whenever a required member is disconnected.
Technical Analysis
The run persists the original locked playerIds, but the shared positional helper removes missing players before evaluating every(). Started-party recovery keeps a partially disconnected run alive for several minutes, creating a window where cooperative gates evaluate only the remaining online subset.
Source Context
selected behavior-pack gameplay bundle — Contains the shared all-player positional predicate, locked run roster, and disconnected-member recovery window.
Must Preserve
  • Exit-vote logic that intentionally uses only online players must keep its separate semantics.
