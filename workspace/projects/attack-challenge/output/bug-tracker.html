01MAJORVERIFIED ISSUE

Ranged enemies replace fatal death with an invulnerable dying-to-despawn path

Marksman and Sharpshooter intercept fatal damage, enter a 4.25-second immobile/invulnerable dying state, then instant-despawn while Attack's explicit NPC defeat settlement is owned by entityDie.

BUG-ATK-RANGED-DEATH-SETTLEMENT
Expected
Every defeated gameplay enemy has clear death feedback and exactly-once kill/score/retry-survivor settlement regardless of terminal presentation.
Observed
The ranged family uses fatal -> deals_damage:no -> start_dying -> movement 0 / damage disabled -> instant_despawn; CombatTracker increments npcKills and killedEntityConfigIds from entityDie.
Technical Analysis
The selected artifact exposes an alternate terminal mechanism for ranged enemies without an explicit shared settlement owner. This also matches the tester-visible abrupt stop/disappearance symptom.
Recommended Fix
Route every enemy terminal path through one explicit exactly-once defeat settlement owner; keep visual death presentation separate from authoritative settlement.

02MAJORVERIFIED ISSUE

03MAJORVERIFIED ISSUE

Last-second flag capture can race timeout through competing terminal paths

FlagService delays victory one tick without a session/generation token; timeout can mutate timing/session state first.

BUG-ATK-LAST-SECOND-DOUBLE-END
Expected
Each attempt has exactly one terminal owner and later terminal callbacks cannot score/retry/advance it again.
Observed
scoreFlag schedules endGame(victory) one tick later; timeout can run first and clear the timestamp used by the later victory guard while scheduling retry.
Technical Analysis
Other delayed retry/advance work is context-guarded; the unguarded FlagService terminal callback is the specific remaining race.
Recommended Fix
Claim terminal outcome atomically per arena/session generation and bind delayed victory to that claim/context.

01DEV NOTE

Entity Selection Stick Is Still Active in Production

EntitySelectionLogger is initialized in the production Attack bootstrap. Any valid player using a normal minecraft:stick records coordinates and receives ctf_attack debug messages; sneaking with the stick removes/clears selections. The handler has no admin check.

DEV-ATK-SELECTION-STICK-PRODUCTION
Action
Remove EntitySelectionLogger from the release bootstrap, or gate the entire tool through the existing PermissionService admin owner. A normal gameplay item should not implicitly activate developer instrumentation.
Evidence

  "artifactVersion": "1.1.10",
  "source": "behavior_packs/BP/scripts/chunks/chunk-DLVKMFJZ.js",
  "finding": "EntitySelectionLogger.init() subscribes to itemUse for minecraft:stick and is called unconditionally by the Attack bootstrap; addSelection() has no PermissionService check."
}

02DEV NOTE

World-Mutating Script Events Do Not Use the Existing Admin Permission Owner

Attack ships an explicit PermissionService, but GameManager script-event handlers for reset/force-start/force-end/skip-level and setup/reset services do not check PermissionService.isAdmin() before mutating session/world state. Command-level reachability may still restrict ordinary players, so this is not classified as an ordinary-player exploit from source alone.

DEV-ATK-SCRIPT-EVENT-PERMISSION
Action
Route developer/admin script-event handlers through one explicit permission gate before performing world or session mutations. Do not rely only on external command reachability as the privilege boundary.
Evidence

  "artifactVersion": "1.1.10",

03DEV NOTE

Admin Grant Secret Is Hard-Coded in the Shipped Behavior Script

permission.config embeds the admin grant/revoke secret directly in the distributed behavior script. Anyone with the world/add-on files can read the value, so it should not be treated as a durable secret boundary.

DEV-ATK-HARDCODED-ADMIN-SECRET
Action
Do not use a shipped static secret as the trust boundary. Prefer operator/host-controlled authorization or another runtime authority that is not recoverable from the distributed pack.
Evidence
