# System

This domain owns durable architecture, semantic ownership, development discipline, specialist routing, developer/delivery operations, project/report ownership, and repository execution efficiency.

It does not own planning, current project state, or chronological proof history.

## Canonical entrypoints

- [Architecture](./architecture.md) — dependency direction, orchestration boundary, and subsystem composition.
- [Authority Model](./authority-model.md) — semantic authority and proof boundaries.
- [Behavioral World Model](./behavioral-world-model.md) — executable state/transition/temporal model boundary.
- [Bug Report Ownership](./bug-report-ownership.md) — current audit truth vs approved Bug Report V2 ownership.
- [Canonical Naming](./canonical-naming.md) — repository-wide terminology and filesystem disambiguation.
- [Development Discipline](./development-discipline.md) — minimum complete change and anti-overdevelopment rules.
- [Development Operations](./development-operations.md) — remote-GitHub-first development, optional local tooling, verification, and delivery routing.
- [Drive Storage](./drive-storage.md) — map/project publication and Drive storage contract.
- [Implementation Map](./implementation-map.md) — human-readable semantic/source ownership index; machine-readable ownership remains enforcement authority.
- [Project Lifecycle](./project-lifecycle.md) — project continuity, approval, publication, and durable issue-history boundaries.
- [Skill Routing](./skill-routing.md) — work-lane structure, specialist selection, permission boundary, and handoff semantics.
- [Zero-Waste Execution](./zero-waste-execution.md) — affected planning, bounded context, context efficiency, reuse, and selective validation.

Repository roadmap/backlog belongs in `planning/`. Current project execution data belongs in `workspace/`. Audit notes, migration diaries, chronological proof logs, and temporary gap lists are not durable system authority.
