# System

This domain owns durable architecture, semantic ownership, development discipline, specialist routing, and developer/delivery operations.

## Canonical entrypoints

- `architecture.md` — dependency direction and subsystem boundaries.
- `authority-model.md` — semantic authority and proof boundaries.
- `canonical-naming.md` — repository-wide terminology and filesystem disambiguation.
- `development-discipline.md` — minimum complete change and anti-overdevelopment rules.
- `development-operations.md` — developer command, toolchain, verification, and delivery routing.
- `implementation-map.md` — exact semantic/source owners.
- `skill-routing.md` — specialist selection and handoff.
- `skill-contract.md` — mandatory work-lane structure and handoff semantics.
- `zero-waste-execution.md` — affected planning, bounded context, reuse, and selective validation.

Audit notes, migration diaries, chronological proof logs, and temporary gap lists are not durable system authority. Consume their findings into the canonical owner, then rely on Git history for the superseded record.
