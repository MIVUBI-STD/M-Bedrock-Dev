# System

This domain owns durable architecture, semantic ownership, development discipline, specialist routing, and developer/delivery operations. It does not own planning, current project state, or chronological proof history.

## Canonical entrypoints

- `architecture.md` — dependency direction and subsystem boundaries.
- `authority-model.md` — semantic authority and proof boundaries.
- `canonical-naming.md` — repository-wide terminology and filesystem disambiguation.
- `development-discipline.md` — minimum complete change and anti-overdevelopment rules.
- `development-operations.md` — developer command, toolchain, verification, and delivery routing.
- `implementation-map.md` — current human-readable semantic/source ownership index; prefer machine-readable ownership for enforcement.
- `skill-routing.md` — work-lane structure, specialist selection, permissions boundary, and handoff semantics.
- `zero-waste-execution.md` — affected planning, bounded context, context efficiency, reuse, and selective validation.

Repository roadmap/backlog belongs in `planning/`. Current project execution data belongs in `workspace/`. Audit notes, migration diaries, chronological proof logs, and temporary gap lists are not durable system authority. Consume their findings into the canonical owner, then rely on Git history for the superseded record.
